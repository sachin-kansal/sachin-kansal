# Hey, I'm Sachin Kansal 👋

### Cloud & DevOps Engineer | Building Towards Platform Engineering & Cloud Architecture

I like understanding how things work behind the scenes — how applications communicate, how infrastructure scales, how systems stay reliable, and how automation makes engineering better.

My journey into infrastructure engineering started with **Google Cloud and Apache Kafka**, where I worked on cloud-based data platforms and distributed messaging systems. Over time, my interests expanded into AWS, Kubernetes, infrastructure automation, security, and observability.

## 🌱 My Journey

I believe the best way to learn infrastructure is to work with it, break things, troubleshoot them, and build them again.

Here's how my journey has evolved:

**01. The Foundation — Google Cloud & Kafka**

Started my professional journey working with Google Cloud Platform and Apache Kafka.

- Worked with GKE and Confluent Kafka clusters.
- Managed distributed messaging infrastructure with 9+ brokers and 200+ topics.
- Worked on Kafka Connect and custom MongoDB source integrations.
- Explored automation and operational improvements for distributed systems.

**02. Expanding Horizons — AWS & Cloud Infrastructure**

Moved deeper into cloud infrastructure, automation, and production operations.

- Worked with AWS, Terraform, Jenkins, and Amazon EKS.
- Built and maintained CI/CD pipelines.
- Worked on cloud cost optimization and infrastructure improvements.
- Implemented monitoring, security scanning, and infrastructure automation.
- Gained exposure to hybrid and on-premises infrastructure.

**03. The Next Chapter — Platform & Cloud Engineering**

Currently working towards deeper expertise in cloud-native infrastructure and platform engineering.

My interests include:

- Kubernetes architecture and cluster administration.
- Infrastructure as Code and GitOps.
- Cloud security and DevSecOps.
- Distributed systems and observability.
- Building reliable, scalable infrastructure platforms.

I am particularly interested in understanding how engineering teams build internal platforms that make application delivery simpler, safer, and faster.

I still have a lot to learn, and that's what makes this journey interesting.
